# Python 없는 셸 설치기 — 2026-09-13

설치·업데이트 진입점은 `bash scripts/install.sh`다. 기본 링크 설치, `--mode copy`, `--dest`, 반복 가능한 `--skill`, `--list`, `--dry-run`, `--help`를 지원한다. Python·Node·jq·패키지 관리자를 호출하지 않는다. 사용자 환경 설정과 스킬 본문은 변경하지 않는다.

## 기존 설치와의 관계

| 기존 상태 | 셸 설치기 동작 |
| --- | --- |
| 같은 원본을 가리키는 링크 | 그대로 재사용 |
| 셸 설치기의 수정 없는 복사본 | 변경이 있으면 갱신 |
| 로컬 수정·파일 추가/삭제·빈 폴더 추가가 있는 복사본 | 보존하고 오류로 안내 |
| Python 설치기로 만든 복사본 | 자동 변환 없이 보존하고 백업·병합 후 재설치 안내 |
| 수동 설치·외부 링크·깨진 링크·설치 모드 변경 | 덮어쓰지 않고 오류로 안내 |

새 복사 형식은 파일 이름·내용과 빈 디렉터리를 포함한 SHA-256을 사용한다. 관리 파일은 실행하거나 source하지 않고 문자열로 검사한다. 스킬 안의 심볼릭 링크·특수 파일은 받지 않는다. 기존 Python 설치기는 이전 복사본 갱신과 개발 검사기의 호환을 위해 남겼으며, 신규 설치에 필요하지 않다.

## 실행한 검증

환경: Linux, Bash 5.2.21. 테스트 입력·설치 대상은 모두 임시 경로다.

- `bash -n scripts/install.sh`: 문법 검사 통과.
- `python3 scripts/validate.py`: 두 스킬 구조·참조 검사 통과.
- `python3 -m unittest discover -s tests -v`: 총 47개 통과. 기존 24개와 새 관리 파일 검사 1개, 셸 CLI 검사 22개다.
- 셸 CLI 테스트에서는 PATH에 필요한 파일 명령만 넣었다. Python·Node·Ruby·jq·realpath·패키지 관리자를 찾을 수 없는 PATH에서 설치를 실행했다. 테스트를 구동하는 Python 프로세스와 설치기 실행 의존성을 구분한다.
- 재실행, 선택 중복 제거, 신규 스킬 발견, 미리보기 무변경, 기존 링크 호환, 복사 갱신, 사용자 변경 보존, 전체 선택의 충돌 사전 검사를 확인했다.
- 공백·한글 경로, 숨김 파일, 빈 폴더, 스킬 내부의 개행·셸 특수문자 파일 이름을 확인했다. checkout·대상 디렉터리 경로의 개행은 명시적으로 거절한다.
- 목적지의 심볼릭 링크와 `..` 처리, 자기 저장소 설치 차단, 기존 복사 형식 보존, 관리 파일을 코드로 실행하지 않는 동작을 확인했다.
- `mv` 실패를 주입해 최초 복사 실패 시 불완전 스킬이 남지 않음, 교체 실패 시 복구, 복구 실패 시 검색 경로 밖 백업 보존을 확인했다.
- 실제 두 스킬을 임시 경로에 링크·복사 설치하고 원본과 파일 내용을 비교했다. 각 모드에서 두 스킬 모두 재실행 시 unchanged를 확인했다.

## 한계

Bash 3.2 호환 문법과 macOS/BSD 호환 옵션으로 작성했지만 macOS 실기 및 Bash 3.2 바이너리에서 실행하지는 않았다. Linux 테스트를 macOS 검증으로 간주하지 않는다.

설치 전체가 하나의 트랜잭션은 아니다. 여러 설치기를 동시에 실행하거나 설치 중 사본을 편집하지 않는다. 복구 검사는 주입한 명령 실패에 한정하며 강제 종료·전원 차단·모든 파일시스템 오류를 보증하지 않는다. 내용 해시는 권한·확장 속성 변경을 감지하지 않는다. Mac의 GitHub 인증과 실제 Codex 스킬 발견은 별도 확인 대상이다.

사용자 설치에는 Python이 필요 없다. 이 저장소의 개발 검사와 기존 Python 복사본을 예전 방식으로 갱신할 때만 Python 3.10 이상을 사용한다.
