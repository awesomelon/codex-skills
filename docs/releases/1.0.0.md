# Rung 1.0.0

Rung 1.0 establishes a stable two-skill engineering contract and verified CLI distribution. The skill instructions are unchanged from 0.5.5. This release adds compatibility policy, a reproducible contract evaluation runner, recorded task and distribution evidence, and explicit limits.

## Stable contract

Use `rung-get-set` for investigation, design, planning, and review without editing the assessed material. Use `rung-go` directly for authorized implementation and verification. Either works independently; Get Set is not a prerequisite. Optional technical references do not expand task authority. The plugin contains skills only and adds no agent runtime or scheduler.

Removing or renaming an entrypoint, making assessment write by default, requiring a Get Set phase, removing standalone support, or breaking documented installer options requires a major version. See [compatibility and versioning](../compatibility.md).

## Verification

The [qualification record](../../evals/runs/2026-10-03-qualification/results.md) contains the exact inputs, hashes, runtime metadata, tool evidence, assertions, and adjudication.

- All 13 contract cases passed independent scope/artifact checks and coordinator adjudication of the response and actual tool evidence. This includes both standalone skill configurations. These are bounded synthetic samples, not a reliability estimate or blinded review.
- Two explicitly invoked tasks read the installed 1.0 plugin's cached skill files and completed correctly.
- Isolated CLI installation, enabled state, update from 0.5.5, restoration of 0.5.5, reinstallation of 1.0, and removal preserved unrelated test configuration and data.
- Real macOS `/bin/bash` checks cover standalone listing, dry run, selected link, both managed copies, repeat/update/recovery, and preservation of locally edited copies. Python is not required by the shell installer.
- Structural validation, Bash syntax, 107 deterministic regression tests, and source/package consistency are recorded separately from model behavior.

The tested behavioral environment is macOS 27.0.1 arm64, Codex CLI 0.160.0, and observed `gpt-6-astra` / `high`. Tool processes used local Python and Node runtimes identified in the records. The temporary evaluation environment disables apps, web access, and multi-agent execution; those restrictions define this study rather than Rung's normal requirements.

A separate [24-attempt comparison pilot](../../evals/runs/2026-10-03-native-pilot/results.md) produced correct artifacts in both control and Rung arms. It demonstrated no additional benefit on those outcomes. No superiority, savings, or universal reliability claim is made. Older pilot tool-event omissions remain documented and were not retroactively filled.

## Migration and recovery

No skill rename, required workflow step, or configuration migration is introduced from 0.5.5. Refresh the marketplace, inspect the installed version, preserve any edits to installed files, and reinstall if needed using the [installation guide](../installation.md). Start a new conversation and use the names shown by its catalog, such as `rung:rung-get-set` and `rung:rung-go`.

For local recovery to 0.5.5, retain a separate checkout of that tag, register it as a local marketplace in an isolated configuration, and remove/reinstall from that source. Confirm the reported version and loaded package path in a fresh session. Preserve edits before native removal, which can delete cached files. Do not rewrite old tags or automatically delete former CraftFlow copies. The qualification lifecycle tested the previous and current manifests with identical skill payloads.

## Known limits

Desktop activation, implicit skill selection, live steering/cancellation/pause/resume, and compaction reliability are not qualified by this release. The changed-instruction and stale-result fixtures are replays. Other OS/model combinations have no behavioral claim from this batch; cross-platform repository CI establishes deterministic checks only. The prior Python copy installer remains supported by its regression tests, while the shell installer remains macOS-specific.

The release process verifies the final remote installation after publication. Its source revision and byte comparison are retained as the release's `published-installation.json` asset, separately from the pre-publication qualification record.
