# Engineering Orchestration plugin

The repository root is a skills-only Codex plugin named `codex-skills`, displayed as **Engineering Orchestration**. Its `.codex-plugin/plugin.json` points directly to `./skills/`. All seven skills keep their standalone names, references, UI metadata, and upstream notices. There is no second copy of the skill content to synchronize.

The package uses the compatibility manifest generated by OpenAI's Plugin Creator. It provides orchestration guidance and specialist expertise using the host's available tools. It adds no MCP server, hooks, scheduler, SDK runner, or configuration changes. Tool availability and permissions remain properties of the current session.

## Install and try the package

Use a Codex or ChatGPT Work host that supports local plugin marketplaces. Start from a durable clone named `codex-skills`, then ask its built-in Plugin Creator:

```text
Add the existing plugin at /absolute/path/to/codex-skills to my local marketplace.
Preserve its manifest and skills. Do not scaffold another copy.
```

Replace the path with the actual clone location. Review the proposed marketplace entry, refresh the host, and install **Engineering Orchestration** from that local source. Open a new conversation and inspect the available skills. Use the actual names advertised there; the host may qualify them with a plugin prefix.

Try these representative requests:

- Coordinate a change across an API producer and its consumer, then verify compatibility.
- Plan an API/cache/UI migration without editing implementation files.
- Review current TypeScript input validation without modifying files.
- Correct one README typo.
- Resume an interrupted change from its checkpoint and current working tree.

Check that coordinated work reaches its requested endpoint, a standalone review preserves files, and a tiny edit stays small. A successful manifest check alone does not establish discovery or execution behavior.

For host verification, retain the host version, OS, source commit, installation route, advertised skill names, exact request, and observed skill/resource loads for each task above. Use a fresh conversation per request and omit explicit skill names when testing automatic selection. Record file changes and observable outcomes separately from the selection result; a correct answer alone does not prove that the host loaded the intended skill. Include a plain explanation request and a typo fix as adjacent negative cases. Keep unobserved selection as unknown rather than inferring it from the answer.

The [repository CI](../.github/workflows/validate.yml) exercises installation mechanics on macOS and Linux. It does not launch Codex or register this package with a native host. Record native-host results separately using the evidence fields above.

When switching from individually installed skills, preserve any local modifications and move superseded entries outside every skill discovery directory before enabling the package. Reconcile existing symlink sources too. The shell installer does not migrate skills into a plugin or remove old entries. For a subset of the collection, keep using the [individual macOS installer](../README.md#install-on-a-new-mac).

## Maintain and validate

Edit the original `skills/` files and validate their structure with `python3 scripts/validate.py`. Validate the root package using the `validate_plugin.py` script supplied by the host's Plugin Creator skill; locate it through that skill rather than assuming a fixed installation path. Keep the manifest's relative skills path and root directory name aligned. Do not add a second root `plugin.json` as a competing manifest.

Before distributing a new package version, repeat representative host tests in a new conversation. Record package validation, model task execution, and native installation separately. Update the version when publishing a new package revision; marketplace registration and public directory submission are separate operations.

This repository provides the package and [evaluation evidence](../evals/orchestration-plugin-2026-09-19/results.md). Native plugin installation and macOS execution were not available in the Linux evaluation environment. No marketplace entry or public directory listing was created by that evaluation.
