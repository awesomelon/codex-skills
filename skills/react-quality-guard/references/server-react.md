# SSR·RSC·Next.js에 해당할 때

실제로 서버 렌더나 서버 함수가 있는 경로에서만 적용한다. Vite SPA에 이 구조를 도입하기 위한 문서가 아니다. 원문과 공식 문서는 [sources.md](sources.md)에 있다.

## 데이터와 서버 경계

- 클라이언트에서 호출 가능한 서버 mutation은 실제 실행 경로에서 인증·대상 리소스 권한을 검증해야 한다. 페이지·레이아웃에서 버튼을 숨기는 것으로 대체하지 않는다.
- 요청·사용자 데이터는 렌더·요청 수명 안에 둔다. 서버 모듈의 mutable 변수나 브라우저용 singleton을 요청 간 공유 상태로 사용하지 않는다. 불변 정적 설정과 의도적으로 설계한 공유 캐시는 구분한다.
- `React.cache()`는 RSC의 요청 내 중복 제거 용도를 확인해 사용한다. 일반 클라이언트 훅 캐시나 요청 간 캐시로 취급하지 않는다. 지속 캐시는 키의 권한·테넌트 범위, 만료·무효화, 프로세스·배포 특성을 먼저 확인한다. LRU를 기본 의존성으로 넣지 않는다.
- RSC에서 클라이언트로 보내는 props는 실제 필요한 공개 데이터만 남긴다. 중복 객체 전송을 줄이는 변경과 전체 전송량·클라이언트 계산 증가를 함께 비교하고, 단순히 같은 참조를 유지하려고 불필요한 원본 데이터를 전송하지 않는다.

## 로딩과 렌더링

- 독립된 데이터 의존성은 병렬로 시작할 수 있는 구조를 검토한다. Suspense는 지원하는 데이터 소스와 사용자에게 의미 있는 로딩 경계에 사용한다. 일반 Effect fetch를 감싼 것만으로 Suspense가 동작한다고 가정하지 않는다.
- 서버 HTML과 클라이언트 최초 렌더가 일치하도록 데이터·시간·ID·환경 접근을 점검한다. `localStorage` 초기화는 서버 접근 가능성과 hydration을 함께 본다.
- `suppressHydrationWarning`이나 사전 DOM 수정 스크립트를 일반적인 해결책으로 삼지 않는다. 불가피한 좁은 예외만 사용하고, 스크립트가 필요하면 서버가 낸 마크업, 안전한 값 처리와 CSP 등 실제 제약을 검증한다.
- `next/dynamic`, `after()`, Activity, React DOM resource hints는 해당 버전·라우터·런타임의 지원과 의미가 확인될 때만 사용한다. 설치된 프레임워크의 기존 기능을 우선한다.
- 응답 후 실행으로 옮길 작업이 핵심 저장·권한·감사 기록 등 완료 보장의 일부인지 확인한다. 보장 수준이 필요한 작업을 단순한 성능 최적화로 비보장 부수 효과로 바꾸지 않는다.

서버 규칙은 이 변경의 실행 경로에 필요한 만큼 확인한다. 관련 없는 백엔드 전체를 감사하거나 클라이언트 리뷰를 서버 재설계로 확대하지 않는다.
