# CraftFlow Go

Deliver the requested change and evidence that it works. Reuse an existing diagnosis or plan; make necessary local design decisions without repeating discovery. Preserve unrelated changes. If asked only to plan, explain, or review, preserve the assessed material and provide that endpoint without implementation.

## Implement at the needed scale

Establish the intended behavior, affected consumers, and completion condition. Resolve consequential intent gaps using authoritative project decisions; do not invent product policy. Keep related responsibilities together and fix shared causes at their owner, while preserving independently changing rules. Choose existing capabilities when their semantics fit. A clear local edit needs no plan artifact, specialist cascade, or extra approval.

For dependent work, keep one compact plan of outcomes, dependencies, owners, and acceptance evidence. Settle shared contracts before parallel writes. Delegate only when independent work warrants the cost and available capabilities allow it; continue useful work locally. Use [coordination](references/workflow/coordination.md) for assignments, ownership, handoffs, and recovery. Workers inherit the task's scope. Use [expertise boundaries](references/workflow/expertise.md) when several technical areas overlap.

Shared-rule design can use Get Set's `references/quality/implementation.md`, and material intent gaps can use Get Set's `references/workflow/spec-driven-changes.md`; neither requires another full workflow.

## Finish with evidence

Inspect the final artifact and behavior where changed contracts meet. Reuse checks for unchanged code and conditions; refresh stale evidence and run required gates. Do not weaken tests or replace missing assertions with a success message. Separate correctness, maintainability judgment, and measured performance.

Resolve and verify in-scope issues, account for blocked outcomes and owned workers/processes, and report actual changes, checks, and material limits. Stop when the requested outcome is sufficiently verified. Commit, publish, merge, and future monitoring follow existing user authorization. Keep a durable lesson only when it qualifies and writing it is in scope. [Source history](references/workflow/sources.md) is for provenance, not required execution reading.
