# 코드 품질 가드

현재 동작의 정확성과 다음 변경의 비용을 따로 판단한다. 테스트 통과를 좋은 설계의 증거로 바꾸거나 AI의 인상 점수를 측정값으로 제시하지 않는다.

## 범위와 작업 방식

리뷰·검사·평가만 요청받았다면 소스·설정·문서를 수정하지 않는다. 개선도 요청받으면 근거 있는 문제를 요청 범위 안에서 수정하고 확인한다. 기존 검사 결과와 관련 리뷰 근거를 재사용한다.

PR은 확인된 base/head와 merge-base, 로컬 작업은 staged·unstaged·untracked를 포함해 비교한다. 작업 후 점검에서는 시작 시점의 사용자 변경과 이번 수정을 구분한다. 비교 자료가 없으면 현재 상태 진단으로 한정한다. 새 문제·악화·기존 부채를 구분하고, diff와 직접 연결된 호출자·계약부터 읽는다. 전체 감사는 조사한 영역과 표본의 한계를 밝힌다.

## 두 가지 판단

- **정확성:** 요구사항·공개 계약·불변조건과 관련 검사 결과를 연결한다. 실행한 명령, 확인한 동작, 실패·미실행·미확인 영역을 구분한다. 테스트가 통과해도 검사하지 않은 경로의 정확성은 보증하지 않는다.
- **유지보수 품질:** 같은 정책의 수정 지점, 숨은 상태와 부작용, 이해에 필요한 추적 경로, 불필요한 추상화, 회귀를 국소적으로 검증할 수 있는지를 살핀다. 파일 길이나 패턴 취향만으로 결함을 만들지 않는다.

반복 가능한 비교·수치 평가에는 [measurement.md](references/measurement.md)를 읽는다. 소규모 리뷰에는 의심되는 문제를 판단할 신호만 사용하며 모든 지표 수집을 요구하지 않는다.

품질 지적은 **파일·심볼의 관찰 → 실제 변경/실패 조건 → 비용이나 위험 → 최소 조치와 확인 방법**을 연결한다. 문서화된 이유나 반례도 확인한다. 같은 원인을 중복 집계하지 않고, 근거가 약하면 확인할 항목으로 남긴다.

다음 변경이 어려운지 불분명하면 요구사항·이력에서 현실적인 작은 변경 하나를 골라 수정 지점과 검증 경로를 추적한다. 예컨대 같은 상태 정책을 바꾸려면 몇 곳의 판단을 함께 고쳐야 하는가? 가정과 실제 실행을 구분하고, 리뷰 중 가상의 기능을 구현하지 않는다. 변경 실험이 요청됐을 때만 격리된 사본에서 구현·회귀 검증하고 비용을 기록한다.

## 개선과 종료

현재 구조 유지, 국소 수정, 경계 조정의 비용을 비교한다. 같은 이유로 바뀌는 정책은 소유자를 모으되, 비슷하게 생겼어도 독립적으로 바뀌는 정책은 유지한다. 정당한 복잡성이나 계약상 필요한 방어 코드를 수치 개선을 위해 없애지 않는다. 미사용 판단은 실제 진입점·동적 등록·재수출까지 확인한다.

개선 후에는 같은 범위·기준으로 전후 근거와 관련 동작을 확인한다. 테스트·lint·타입 규칙을 약화하거나 파일 이동·코드 압축으로 숫자만 낮추지 않는다. 필수 검증과 남은 구체적 위험을 확인한 뒤 선택적 정리만 남으면 종료한다. 점수를 올리기 위한 반복 개선은 하지 않는다.

결과는 요청한 형식으로 정확성 상태와 품질 판단을 구분하고, 중요한 근거·최소 조치·남은 불확실성을 제시한다. 품질 변화는 근거가 있을 때만 개선·유지·악화로 말하고 그 외에는 판단 보류로 둔다. 중대한 정확성·보안·데이터 정합성 문제를 품질 점수로 상쇄하지 않는다. 수치 점수가 요청되면 측정 참조의 제한을 따른다.

아키텍처 경계나 React 실행 방식도 쟁점이면 해당 전문 리뷰의 근거를 재사용한다. 다른 스킬이 없어도 이 검사는 수행하며, 모든 스킬을 연쇄 호출하거나 동일 문제를 다시 보고할 필요는 없다.
