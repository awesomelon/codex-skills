# 아키텍처 독립 리뷰 출력

별도 에이전트의 최종 답변이다. 파일 링크만 저장소 경로로 변경했다.

중요한 문제는 **1건**입니다.

- **명시된 의존 방향 위반과 기능 간 숨은 상태 결합**  
  [core/http.ts](../fixtures/architecture/core/http.ts)의 `getJSON`은 `features/documents/store.ts`를 직접 가져와 `documentStore.workspaceId`를 요청 헤더로 사용합니다. 이는 금지된 `core → 기능 코드` 의존입니다. 실제로 `loadInvoices → getJSON → documentStore.workspaceId` 경로 때문에 청구 조회의 워크스페이스도 문서 기능 상태가 결정합니다. 두 기능의 대상 워크스페이스가 달라지면 청구 요청이 의도와 다른 워크스페이스로 전송될 수 있습니다. 다만 서버가 이를 허용하는지는 자료에 없으므로 권한 우회로 단정할 수 없습니다.  
  **최소 조치:** `getJSON`이 워크스페이스 ID를 인자로 받도록 하고, `loadInvoices`도 호출자로부터 해당 ID를 받아 전달하게 합니다. 별도 공통 계층 도입 없이 직접 의존과 숨은 상태 읽기를 제거할 수 있습니다. **확인 방법:** core의 기능 코드 의존이 없어졌는지 확인하고, 문서 저장소 상태와 무관하게 청구 요청 헤더가 전달받은 ID를 사용하는지 검증합니다.

`adapters/document-export.ts`의 저장소 접근은 명시적으로 허용된 예외이므로 문제로 지적하지 않았습니다. 내보내기 권한은 호출 전에 서버에서 검증한다는 조건을 적용했습니다.

검토 범위는 제공된 소스 4개 전체의 import, 호출 경로, 상태 읽기와 공개 함수 계약입니다. 파일 수정·네트워크 접속·패키지 설치 없이 정적으로 검토했습니다. 이전 커밋·diff·실행 의존성이 없어 회귀 여부와 런타임 동작은 검증하지 못했으며, 외부 호출자·서버 처리·워크스페이스 전환 로직은 확인할 수 없습니다.
